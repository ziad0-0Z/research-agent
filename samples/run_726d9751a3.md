# Research Report: Processing Customer Financial Data with a Self-Hosted LLM

## Executive summary
Deploying a self-hosted LLM for customer financial data is feasible but requires strict adherence to regulatory oversight and security controls. While self-hosting offers infrastructure control, the bank remains fully responsible for data compliance, security, and risk management. Technology leadership should proceed with a pilot conditional on prior approval from compliance and risk functions, alongside implementation of robust infrastructure patching, access controls, and audit logging.

## Findings
1. Regulated financial institutions remain fully responsible for customer financial data processed by AI models, regardless of whether the infrastructure is in-house or third-party. [id:ev10] _(evidence: strong)_
2. Self-hosting does not remove compliance obligations; institutions must demonstrate access controls, audit logging, model change management, and incident response. [id:ev11] _(evidence: strong)_
3. Moving customer financial data processing to a new AI deployment model requires prior approval from the institution's compliance and risk functions. [id:ev12] _(evidence: strong)_
4. Self-hosted LLM architectures require verifying downloaded model weights against checksums, regular server patching, authenticated inference endpoints, and audit logs. [id:ev1], [id:ev2], [id:ev3], [id:ev4] _(evidence: strong)_
5. Self-hosting does not protect against prompt injection, requiring applications to treat user input and retrieved documents as untrusted. [id:ev1], [id:ev5] _(evidence: strong)_
6. On-demand rental for a single inference-class GPU ranges from $1.50 to $4.00 per hour, totaling roughly $1,100 to $2,900 per month per GPU before storage, networking, and monitoring. [id:ev6], [id:ev7] _(evidence: moderate)_
7. Serving 7-14B parameter models comfortably requires a single high-memory GPU, while 70B-class models require two to four GPUs. [id:ev8] _(evidence: moderate)_

## Recommendation
Do not deploy production workloads immediately; instead, secure formal approval from compliance and risk functions first. Revisit full deployment when infrastructure security hardening, prompt injection mitigations, and cost-per-token models are fully validated.

**Impact:** high

## Limitations
- Market cost data relies on general cloud provider estimates rather than enterprise-specific banking grid infrastructure costs.
- Specific details on internal bank latency requirements and fine-tuning pipeline data throughput are not covered by the evidence.
