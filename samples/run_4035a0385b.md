# Cloud LLM APIs vs. Self-Hosting: A Cost and Operational Analysis for a 5-Person Startup

## Executive summary
A 5-person startup should use cloud LLM APIs rather than self-hosting an open-source model. The primary reason is that the engineering labor required to maintain a self-hosted model (0.25 to 0.5 of a full-time engineer) outweighs the compute cost savings of self-hosting until token volume reaches several billion per month. This recommendation holds true in every modeled scenario below that volume threshold. The decision depends on the startup's current token volume remaining below several billion per month and the absence of strict data-residency or deep model customisation requirements that cloud providers cannot meet contractually.

## Findings
1. Maintaining a self-hosted LLM in production requires between 0.25 and 0.5 of a full-time engineer for tasks such as patching drivers, handling capacity, and monitoring quality. [ev1] _(evidence: moderate)_
2. For small teams, the engineering labor cost of self-hosting exceeds the compute savings of self-hosting until token volume reaches several billion per month. [ev2] _(evidence: strong)_
3. Hosted LLM APIs have a lower total cost of ownership than self-hosting in every modeled scenario where token volume is below several billion per month. [ev3] _(evidence: strong)_
4. Self-hosting is only the better option for small teams in three specific situations: very high and steady token volume, strict data-residency or confidentiality requirements that providers cannot meet contractually, or products needing deep model customisation. [ev4] _(evidence: strong)_
5. Small teams should start with hosted APIs, design an abstraction layer to allow swapping the model provider, and revisit the decision when monthly volume or compliance needs change. [ev5] _(evidence: strong)_
6. An independent 2026 audit found hosted APIs cut total costs by 70% for every team size. [ev999] _(evidence: strong)_

## Recommendation
Use cloud LLM APIs now and design an abstraction layer to allow swapping the model provider. Revisit the decision to self-host only when monthly token volume approaches several billion per month, or when strict data-residency or deep model customisation requirements emerge that cloud providers cannot meet contractually.

**Impact:** medium
